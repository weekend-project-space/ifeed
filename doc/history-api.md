# 阅读历史接口与 PostgreSQL 存储

本文整理文章阅读历史的接口和 PostgreSQL 表结构。保留现有三个接口路径和响应格式，内部关联统一使用数字 ID。

## 1. 接口概览

| 功能 | 方法 | 路径 |
|---|---|---|
| 记录／更新阅读历史 | POST | `/api/user/history` |
| 删除阅读历史 | DELETE | `/api/user/history/{articleId}` |
| 阅读历史列表（Pageable） | GET | `/api/user/history` |

三个接口均要求 `Authorization: Bearer <token>`。用户身份由登录信息确定，只能访问自己的阅读历史，请求不传 `userId`。

## 2. 记录／更新阅读历史

`POST /api/user/history`

```json
{
  "articleId": "7c3db9d8-10a0-4a69-9f3c-2f1b1d0b7d22",
  "readAt": "2026-09-21T08:00:00Z"
}
```

- `articleId` 必填，使用现有文章 UUID。服务端通过 `articles.uid` 查到内部 `articles.id` 后入库。
- `readAt` 可选，省略或为 `null` 时使用服务器当前时间；时间使用 ISO 8601 UTC 格式。
- 同一用户、同一文章只保留一条记录，表示最近一次阅读，不逐次记录阅读事件。
- 重复阅读更新 `read_at`，取已存时间与本次时间的较大值，防止延迟请求或迁移回填覆盖更新的阅读时间。
- 文章不存在返回 `404`。
- 保留现有的 Feed 已读时间更新行为；Feed 已读记录存于 PostgreSQL，其时间同样不应被较早请求覆盖。

响应：`200 OK`。

```json
{
  "message": "History recorded."
}
```

## 3. 删除阅读历史

`DELETE /api/user/history/{articleId}`

请求体无，`articleId` 为文章 UUID。删除当前用户对该文章的阅读记录，不影响收藏、喜欢和 Feed 已读记录。

响应：`200 OK`。

```json
{
  "message": "History deleted."
}
```

保持现有行为：记录不存在返回 `404`，格式不合法返回 `400`。再次阅读该文章会重新创建阅读记录。

## 4. 阅读历史列表（Pageable）

`GET /api/user/history?page=0&size=20&sort=readAt,desc`

| 参数 | 默认值 | 说明 |
|---|---|---|
| `page` | `0` | 从 0 开始 |
| `size` | `20` | 每页 1～100 条 |
| `sort` | `readAt,desc` | 支持按 `readAt` 升序或降序，兼容旧字段别名 `timestamp` |

排序后追加内部 `id ASC`，保证时间相同时顺序稳定。分页、排序、计数均在 PostgreSQL 完成。分页响应沿用 Spring Data `Page`，下面仅展示五个主要字段：

```json
{
  "content": [
    {
      "articleId": "7c3db9d8-10a0-4a69-9f3c-2f1b1d0b7d22",
      "title": "PostgreSQL 索引使用指南",
      "feedTitle": "技术周刊",
      "thumbnail": "https://example.com/cover.jpg",
      "summary": "介绍常见索引的使用方式。",
      "readAt": "2026-09-21T08:00:00Z"
    }
  ],
  "totalElements": 1,
  "totalPages": 1,
  "number": 0,
  "size": 20
}
```

展示字段缺失时可返回 `null`。空列表总数和总页数为 `0`；超出末页返回空 `content`，总数仍为实际记录数。物理删除文章后，对应阅读历史级联删除，不再计入列表或总数。

## 5. PostgreSQL 表结构

表名：`user_read_history`。

| 字段 | 类型 | 可空 | 说明 |
|---|---|---|---|
| `id` | `BIGINT` | 否 | 自增主键，仅内部使用 |
| `user_id` | `BIGINT` | 否 | 关联 `users.id` |
| `article_id` | `BIGINT` | 否 | 关联 `articles.id` |
| `read_at` | `TIMESTAMPTZ` | 否 | 最近一次阅读时间 |

```sql
CREATE TABLE user_read_history (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL,
    article_id BIGINT NOT NULL,
    read_at TIMESTAMPTZ NOT NULL,
    CONSTRAINT uq_user_read_history_user_article UNIQUE (user_id, article_id),
    CONSTRAINT fk_user_read_history_user
        FOREIGN KEY (user_id) REFERENCES users (id) ON DELETE CASCADE,
    CONSTRAINT fk_user_read_history_article
        FOREIGN KEY (article_id) REFERENCES articles (id) ON DELETE CASCADE
);

CREATE INDEX idx_user_read_history_user_read
    ON user_read_history (user_id, read_at DESC, id ASC);

CREATE INDEX idx_user_read_history_article
    ON user_read_history (article_id);
```

所有新表 ID 对应 Java `Long`，不增加 UUID 字段。列表通过 `article_id = articles.id` 关联文章，再将文章 `uid` 作为对外 `articleId` 返回。

`(user_id, article_id)` 唯一约束支持并发更新和按用户、文章删除；两个普通索引分别支持默认分页排序与按文章级联清理。取消阅读记录直接删除行，不增加删除标记、阅读次数或事件明细。

现有 `User.id` 仍为 `Integer`，在应用入口转为 `Long`。PostgreSQL 支持 `BIGINT user_id` 外键关联已有 `INTEGER users.id`，此次无需全局迁移用户主键。

## 6. 数据访问范围

- 阅读历史接口读写 PostgreSQL `user_read_history`。
- 推荐的最近阅读序列、用户兴趣画像读取 PostgreSQL 阅读历史、收藏和喜欢数据。
- Feed 已读状态读写 PostgreSQL `user_read_feeds`，文章阅读和 Feed 已读更新在同一数据库内完成。

## 7. 历史数据迁移记录

历史阅读、收藏、喜欢和 Feed 已读数据已经统一到 PostgreSQL。迁移入口和一次性迁移工具已从应用代码中移除，当前部署只需执行 Flyway 脚本：

- `V3__migrate_read_history_to_postgres.sql` 创建文章阅读历史表。
- `V4__add_collections_and_likes.sql` 创建收藏夹、收藏和喜欢表。
- `V5__add_read_feed_state.sql` 创建 Feed 已读状态表。

这些脚本属于数据库版本历史，必须保留并按 Flyway 顺序执行；应用运行时不再依赖其他数据存储。

## 8. 错误响应

沿用项目 `ErrorResponse` 字段：`timestamp`、`status`、`error`、`message`、`path`。

| 状态码 | 场景 |
|---|---|
| `400` | 文章 UUID、阅读时间、分页或排序参数不合法 |
| `401` | 未登录或登录已失效 |
| `404` | 记录阅读时文章不存在，或删除时阅读记录不存在 |
| `500` | 服务端异常 |
